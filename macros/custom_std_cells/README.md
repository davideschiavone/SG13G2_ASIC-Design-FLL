# Custom (AION) standard cells

`aion_cells.v` holds combinational "super-cells" generated by `aion_opt`: each module is a small
netlist of IHP `sg13g2_*` standard cells, with no behavioural description of what it is supposed
to compute. This directory adds a generator that produces an **exhaustive, self-checking
testbench per module** so that claim can be verified mechanically after every regeneration of the
netlist.

```text
📁 custom_std_cells/
├─ aion_cells.v            # the netlist under test (tracked)
├─ Makefile                # pre-fills the ihp-sg13g2 paths, drives the generator (tracked)
├─ 📁 scripts/
│  └─ gen_cell_tb.py       # the generator (tracked)
└─ 📁 tb/                  # ENTIRELY GENERATED, git-ignored -- see .gitignore
   ├─ tb_<module>.sv       # one exhaustive testbench per module
   ├─ Makefile             # runs them under Verilator and Icarus
   ├─ gold_functions.md    # per module: Liberty functions, gold equations, truth tables
   ├─ README.md            # generated notes about the testbenches themselves
   └─ 📁 build/            # simulator build products
```

Nothing under `tb/` is tracked: it is fully reproducible from `aion_cells.v` plus the PDK, so it
would only ever go stale in git when the netlist changes.

## Usage

Everything runs inside the EDA container — the Liberty file and the cell simulation models live
under `/foss/pdks`, which the host cannot see.

```bash
# generate tb/ and run all testbenches under both simulators
./run.sh "make -C macros/custom_std_cells all"

# or step by step
./run.sh "make -C macros/custom_std_cells generate"     # (re)generate tb/
./run.sh "make -C macros/custom_std_cells verilator"
./run.sh "make -C macros/custom_std_cells icarus"
./run.sh "make -C macros/custom_std_cells help"
```

`verilator`, `icarus` and `all` regenerate `tb/` automatically if `aion_cells.v` or the generator
is newer than it.

| Target | What it does |
| --- | --- |
| `help` | list the targets (default target) |
| `generate` | run `gen_cell_tb.py` and (re)write `tb/` |
| `verilator` | run every generated testbench with Verilator |
| `icarus` | run every generated testbench with Icarus Verilog |
| `all` | both simulators |
| `clean` | delete the whole generated `tb/` directory |
| `clean-build` | delete only `tb/build/`, keep the generated testbenches |

| Variable | Default | Meaning |
| --- | --- | --- |
| `PDK_ROOT` | `/foss/pdks` | root of the PDK install |
| `PDK` | `ihp-sg13g2` | PDK name |
| `LIB` | `$(PDK_ROOT)/$(PDK)/libs.ref/sg13g2_stdcell/lib/sg13g2_stdcell_typ_1p20V_25C.lib` | Liberty file used as the gold oracle. Any corner works — the `function` attributes are corner-independent |
| `CELL_V` | `.../verilog/sg13g2_stdcell.v .../verilog/sg13g2_udp.v` | cell simulation models |
| `NETLIST` | `aion_cells.v` | netlist under test |
| `TB_DIR` | `tb` | output directory |

A passing run prints one line per module per simulator, and exits non-zero if any module fails:

```
[PASS] AION_a21o_and2_xor2_0 : 32/32 vectors match
...
verilator: all 16 testbenches passed
icarus: all 16 testbenches passed
```

## `scripts/gen_cell_tb.py`

Pure Python, no third-party dependencies. **Every library path is an explicit argument**, so the
script is not tied to this PDK or this netlist — the Makefile above only exists to fill in the
SG13G2 paths for convenience.

```
gen_cell_tb.py <netlist.v> --lib FILE [--cell-verilog FILE]... [-o DIR]
               [--max-inputs N] [--no-strip-specify] [--no-makefile]
```

| Argument | Required | Default | Meaning |
| --- | --- | --- | --- |
| `<netlist.v>` | yes | — | structural Verilog netlist to read |
| `--lib FILE` | yes | — | Liberty file whose `function` attributes are the gold oracle |
| `--cell-verilog FILE` | unless `--no-makefile` | — | simulation model for the standard cells, baked into the generated `tb/Makefile`. Repeat the flag for several files |
| `-o`, `--outdir DIR` | no | `<netlist dir>/tb` | where to write the generated files |
| `--max-inputs N` | no | `16` | refuse any module with more inputs than this, instead of emitting a testbench with `2^N` vectors that would never finish |
| `--no-strip-specify` | no | off | compile the cell models as-is. By default the generated Makefile strips their `specify` blocks first — these testbenches check function, not timing |
| `--no-makefile` | no | off | emit only `tb_*.sv` and `gold_functions.md` |
| `-h`, `--help` | | | usage |

Example, spelled out in full:

```bash
python3 scripts/gen_cell_tb.py aion_cells.v \
    --lib          $PDK_ROOT/ihp-sg13g2/libs.ref/sg13g2_stdcell/lib/sg13g2_stdcell_typ_1p20V_25C.lib \
    --cell-verilog $PDK_ROOT/ihp-sg13g2/libs.ref/sg13g2_stdcell/verilog/sg13g2_stdcell.v \
    --cell-verilog $PDK_ROOT/ihp-sg13g2/libs.ref/sg13g2_stdcell/verilog/sg13g2_udp.v
```

### How it works

1. **Parse the netlist** — modules, their `input`/`output`/`wire` declarations, and every
   `<cell> <inst> ( .pin(net), ... );` instance. Port order comes from the module header.
2. **Parse the Liberty file** for the referenced cells only, collecting each pin's `direction`
   and each output pin's `function`.
3. **Parse each Liberty function** into an AST with a recursive-descent parser using Liberty
   precedence — `+`/`|` (OR) < `^` (XOR) < `*`/`&`/juxtaposition (AND) < `!` prefix and `'`
   postfix (NOT) < atom — then render it as a fully parenthesised SystemVerilog expression.
4. **Build the gold model**: one continuous assign per cell instance, with the formal pins
   substituted by the gold name of the connected net (a primary input keeps its own name,
   anything else becomes `g_<net>`), then topologically sorted.
5. **Self-check in Python** by evaluating the gold model over all `2^NI` vectors before writing
   anything, which also proves the model is loop-free and resolvable.
6. **Write** `tb_<module>.sv`, `gold_functions.md`, `tb/Makefile` and `tb/README.md`.

Output is deterministic: re-running on an unchanged netlist rewrites byte-identical files.

### Errors it refuses to generate through

The generator aborts with a message rather than emitting a testbench it cannot justify:

* **an instance that is not a standard cell of `--lib`** — a sub-module defined in the netlist
  itself, a cell from another library, or a typo. Without a Liberty entry there is no function to
  build a gold model from, so this is a hard error naming the offending modules;
* a cell that *is* in Liberty but has no `function` on an output pin — i.e. sequential or
  black-box cells, which this exhaustive-combinational scheme cannot check;
* an instance pin that is not a pin of that cell, or an unconnected cell output;
* an undriven or multiply-driven net, or a combinational loop (the cycle is printed);
* a module with more inputs than `--max-inputs`;
* a port name that would collide with an identifier the testbench template declares.

## What the testbenches check

Each `tb_<module>.sv` sweeps **every** input combination and XORs the DUT outputs against the gold
model:

```systemverilog
wire [NO-1:0] diff    = dut_o ^ gold_o;
wire          correct = (diff === '0);
```

A mismatch prints the offending vector and ends in `$fatal`, so the simulator exits non-zero.

The gold model is **not** derived from the Verilog being tested — it comes from the Liberty
`function` attributes. Gold signals never read a DUT signal; only the netlist's *wiring* is shared
between the two models, and the cell semantics come from an independent source. `tb/gold_functions.md`
lists, per module, the Liberty function used for each instance, the emitted gold equations, the
outputs flattened down to the primary inputs, and the truth tables.

### Why not `sp2bool`?

The container ships lctime's `sp2bool`, which derives boolean functions straight from a transistor
netlist — the obvious oracle. It does not work on this PDK:

* `lctime/lccommon/net_util.py::get_channel_type()` calls a device NMOS only if its model name
  *starts with* `n`. IHP's models are `sg13_lv_nmos` / `sg13_lv_pmos`, so every transistor is
  treated as a PMOS and even `sg13g2_inv_1` comes out as `Y = True`.
* With the model names shimmed to `nmos_lv`/`pmos_lv`, it still mis-solves the deeper series
  stacks: `sg13g2_nand3_1`, `sg13g2_nand4_1` and `sg13g2_nor3_1` — 3 of the 16 cells used by
  `aion_cells.v` — come back as constant `True`/`False`.

The Liberty functions used instead were cross-checked against a direct transistor-network solve of
`sg13g2_stdcell.cdl` (union-find connectivity to VDD/VSS per input vector) and agree for every cell
used here.
