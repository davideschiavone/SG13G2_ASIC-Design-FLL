# Custom (AION) standard cells

`aion_cells.v` holds combinational "super-cells" generated by `aion_opt`: each module is a small
netlist of IHP `sg13g2_*` standard cells, with no behavioural description of what it is supposed
to compute. This directory adds a generator that produces **exhaustive, self-checking testbenches**
so that claim can be verified mechanically after every regeneration of the netlist — at two levels:

* **`tb/sv/`** — SystemVerilog, run under Verilator and Icarus. Checks the netlist against the
  Verilog cell models.
* **`tb/spice/`** — ngspice, run against the real `sg13g2` transistors. Also the place where a
  **hand-written alternative implementation** can be proved equivalent.

```text
📁 custom_std_cells/
├─ aion_cells.v            # the netlist under test (tracked)
├─ Makefile                # pre-fills the ihp-sg13g2 paths, drives the generator (tracked)
├─ 📁 scripts/
│  └─ gen_cell_tb.py       # the generator (tracked)
└─ 📁 tb/                  # ENTIRELY GENERATED, git-ignored -- see .gitignore
   ├─ gold_functions.md    # per module: Liberty functions, gold equations, truth tables
   ├─ 📁 sv/               # tb_<module>.sv, Makefile, README.md, build/
   └─ 📁 spice/            # tb_<module>.spice, reference_cells.spice, Makefile, README.md, build/
```

Nothing under `tb/` is tracked: it is fully reproducible from `aion_cells.v` plus the PDK, so it
would only ever go stale in git when the netlist changes.

## Usage

Everything runs inside the EDA container — the Liberty file, the cell models and the device models
all live under `/foss/pdks`, which the host cannot see.

```bash
# generate tb/ and run everything: Verilator, Icarus and ngspice
./run.sh "make -C macros/custom_std_cells all"

# or one layer at a time
./run.sh "make -C macros/custom_std_cells sv"        # Verilator + Icarus
./run.sh "make -C macros/custom_std_cells spice"     # transistor level
./run.sh "make -C macros/custom_std_cells help"
```

`sv`, `spice` and `all` regenerate `tb/` automatically if `aion_cells.v` or the generator is newer.

| Target | What it does |
| --- | --- |
| `help` | list the targets (default target) |
| `generate` | run `gen_cell_tb.py` and (re)write `tb/` |
| `verilator` | run the SystemVerilog testbenches with Verilator |
| `icarus` | run the SystemVerilog testbenches with Icarus Verilog |
| `sv` | both digital simulators |
| `spice` | run the transistor-level testbenches with ngspice |
| `all` | `sv` then `spice` |
| `wave-sv` | open a SystemVerilog waveform in GTKWave (`TB=tb_<module>`) |
| `wave-spice` | open a SPICE waveform in GTKWave (`TB=tb_<module>`) |
| `clean` | delete the whole generated `tb/` directory |
| `clean-build` | delete only the build products, keep the generated testbenches |

| Variable | Default | Meaning |
| --- | --- | --- |
| `PDK_ROOT` | `/foss/pdks` | root of the PDK install |
| `PDK` | `ihp-sg13g2` | PDK name |
| `LIB` | `.../lib/sg13g2_stdcell_typ_1p20V_25C.lib` | Liberty file used as the gold oracle. Any corner works — the `function` attributes are corner-independent |
| `CELL_V` | `.../verilog/sg13g2_stdcell.v .../verilog/sg13g2_udp.v` | Verilog cell models |
| `CELL_SP` | `.../spice/sg13g2_stdcell.spice` | SPICE cell subckts |
| `MODEL_LIB` | `.../ngspice/models/cornerMOSlv.lib` | device models |
| `MODEL_SECTION` | `mos_tt` | corner selected out of `MODEL_LIB` |
| `VDD` | `1.2` | supply for the SPICE testbenches |
| `CUSTOM` | *(empty)* | SPICE file(s) with your own implementation — see below |
| `MODULE` | *(empty)* | restrict generation to one or more modules |
| `NETLIST` | `aion_cells.v` | netlist under test |
| `TB_DIR` | `tb` | output directory |

A passing run prints one line per module per simulator and exits non-zero if anything failed:

```
[PASS] AION_a21o_and2_xor2_0 : 32/32 vectors match
...
verilator: all 16 testbenches passed
icarus: all 16 testbenches passed
[PASS] AION_a21o_and2_xor2_0 : 32/32 vectors match (2-way: gold, reference)
...
ngspice: all 16 testbenches passed
```

The whole SPICE suite (16 modules, 1384 vectors, real transistors) takes about 10 s.

### Working on one module

Both `MODULE=` and `CUSTOM=` force a regeneration, and `MODULE=` makes the generator emit **only**
those modules — SV and SPICE alike — and remove testbenches left over from a previous run, so the
tree always shows exactly what was last generated:

```bash
./run.sh "make -C macros/custom_std_cells spice MODULE=AION_nand2_11"
./run.sh "make -C macros/custom_std_cells all   MODULE=AION_nand2_11 MODULE=AION_a22oi_inv_10"
```

Run `make generate` with no `MODULE=` to get the full set back.

### Checking a custom implementation

This is what the SPICE layer is really for. Write a SPICE file with a `.subckt` **named exactly
like the Verilog module** and pass it in:

```bash
./run.sh "make -C macros/custom_std_cells spice \
            MODULE=AION_nand2_11 CUSTOM=/foss/designs/.../my_cells.spice"
```

Each deck then requires **three** implementations to agree at every strobe, with all three pairwise
comparisons checked separately so a failure says which one is the odd one out:

```
[FAIL] AION_nand2_11 : custom vs gold -- first mismatch at vector 0 (t=7.80475e-10 s)
[FAIL] AION_nand2_11 : custom vs reference -- first mismatch at vector 0 (t=7.80475e-10 s)
```

(gold↔reference staying silent there is the point: the netlist is fine, the new circuit is not.)

The port order is checked by the generator and must be the Verilog module's own port order —
inputs, then outputs, as declared in the module header — followed by `VDD VSS`:

```spice
.subckt AION_nand2_11 I0 I1 I2 O0 VDD VSS
Xi0 n1 I2 VDD VSS sg13g2_inv_1
Xa0 O0 I0 I1 n1 VDD VSS sg13g2_a21o_1
.ends
```

Get it wrong and the generator refuses to emit, printing the exact `.subckt` line it expected. Your
subckt keeps the plain module name; the implementation from `aion_cells.v` is renamed
`reference_<module>` in `tb/spice/reference_cells.spice`, so there is never any doubt which one a
message refers to.

### Waveforms

Off by default in both layers. The quickest route is one `wave` target per layer — it simulates
with dumping on, converts if needed, and opens GTKWave:

```bash
./run.sh "make -C macros/custom_std_cells wave-sv    TB=tb_AION_nand2_11"
./run.sh "make -C macros/custom_std_cells wave-spice TB=tb_AION_nand2_11"
```

**GTKWave is a GUI**, so run those from a terminal on the noVNC desktop
(http://localhost/?password=abc123) — a headless `./run.sh` will just block. `DISPLAY` defaults
to `:1`, the noVNC display.

To only produce the files, without opening anything:

```bash
./run.sh "make -C macros/custom_std_cells verilator VCD=1"       # tb/sv/build/vlt/<tb>/<tb>.vcd
./run.sh "make -C macros/custom_std_cells icarus    VCD=1"       # tb/sv/build/icarus/<tb>.vcd
./run.sh "make -C macros/custom_std_cells/tb/spice  raw"         # tb/spice/build/<tb>.raw
./run.sh "make -C macros/custom_std_cells/tb/spice  vcd"         # tb/spice/build/<tb>.vcd
find macros/custom_std_cells/tb -name '*.vcd'
```

GTKWave cannot read an ngspice rawfile, so the SPICE decks `set filetype=ascii` and
`mixed_signal/raw2vcd.py` converts it (`RAW2VCD` in the Makefile). Every node becomes a VCD `real`,
which GTKWave draws as an analog trace — you see the real switching waveforms, not just 0/1.

What to look at in a SPICE waveform: the inputs, the strobe `clk`, each implementation's outputs
(`g_<out>` gold, `<out>_ref` reference, `<out>_cus` custom), and the gated error signals
`c_gold_ref`, `c_gold_cus`, `c_ref_cus` — flat 0 on a passing run, pulsing to 1 in the strobe
window of whichever vector failed. On the SV side `diff` and `correct` play the same role.

## `scripts/gen_cell_tb.py`

Pure Python, no third-party dependencies. **Every library path is an explicit argument**, so the
script is not tied to this PDK or this netlist — the Makefile above only exists to fill in the
SG13G2 paths for convenience.

```
gen_cell_tb.py <netlist.v> --lib FILE [--cell-verilog FILE]... [--cell-spice FILE]...
               [--model-lib FILE] [--model-section NAME] [--custom-netlist FILE]...
               [--module NAME]... [--emit {sv,spice,both}] [-o DIR]
               [--vdd V] [--period T] [--tstep T]
               [--max-inputs N] [--no-strip-specify] [--no-makefile]
```

| Argument | Required | Default | Meaning |
| --- | --- | --- | --- |
| `<netlist.v>` | yes | — | structural Verilog netlist to read |
| `--lib FILE` | yes | — | Liberty file whose `function` attributes are the gold oracle |
| `--cell-verilog FILE` | for `sv` | — | Verilog cell models, baked into `tb/sv/Makefile`. Repeatable |
| `--cell-spice FILE` | for `spice` | — | SPICE cell subckts, used to build `reference_cells.spice` and included by each deck. Repeatable |
| `--model-lib FILE` | for `spice` | — | device model library |
| `--model-section NAME` | no | `mos_tt` | section of `--model-lib` to select with `.lib`; empty for a plain `.include` |
| `--custom-netlist FILE` | no | — | alternative implementation(s) to check for equivalence. Repeatable |
| `--raw2vcd FILE` | no | — | rawfile-to-VCD converter, baked into the SPICE Makefile's `wave`/`vcd` targets |
| `--module NAME` | no | *(all)* | generate only this module, SV and SPICE alike. Repeatable |
| `--emit {sv,spice,both}` | no | `both` | which testbenches to generate |
| `-o`, `--outdir DIR` | no | `<netlist dir>/tb` | output root; SV lands in `<DIR>/sv`, SPICE in `<DIR>/spice` |
| `--vdd V` | no | `1.2` | supply, and the `VTH = VDD/2` used to threshold analog nodes |
| `--period T` | no | `1n` | one input vector per period; the strobe is its last 20 % |
| `--tstep T` | no | `50p` | transient output step |
| `--max-inputs N` | no | `16` | refuse any module with more inputs than this, instead of emitting a testbench with `2^N` vectors that would never finish |
| `--no-strip-specify` | no | off | compile the Verilog cell models as-is. By default the generated Makefile strips their `specify` blocks first — these testbenches check function, not timing |
| `--no-makefile` | no | off | emit only the testbenches and `gold_functions.md` |

Example, spelled out in full:

```bash
python3 scripts/gen_cell_tb.py aion_cells.v \
    --lib           $PDK_ROOT/ihp-sg13g2/libs.ref/sg13g2_stdcell/lib/sg13g2_stdcell_typ_1p20V_25C.lib \
    --cell-verilog  $PDK_ROOT/ihp-sg13g2/libs.ref/sg13g2_stdcell/verilog/sg13g2_stdcell.v \
    --cell-verilog  $PDK_ROOT/ihp-sg13g2/libs.ref/sg13g2_stdcell/verilog/sg13g2_udp.v \
    --cell-spice    $PDK_ROOT/ihp-sg13g2/libs.ref/sg13g2_stdcell/spice/sg13g2_stdcell.spice \
    --model-lib     $PDK_ROOT/ihp-sg13g2/libs.tech/ngspice/models/cornerMOSlv.lib
```

### How it works

1. **Parse the netlist** — modules, their `input`/`output`/`wire` declarations, and every
   `<cell> <inst> ( .pin(net), ... );` instance. Port order comes from the module header.
2. **Parse the Liberty file** for the referenced cells only, collecting each pin's `direction`
   and each output pin's `function`.
3. **Parse each Liberty function** into an AST with a recursive-descent parser using Liberty
   precedence — `+`/`|` (OR) < `^` (XOR) < `*`/`&`/juxtaposition (AND) < `!` prefix and `'`
   postfix (NOT) < atom.
4. **Build the gold model**: one assign per cell instance, with the formal pins substituted by the
   gold name of the connected net (a primary input keeps its own name, anything else becomes
   `g_<net>`), then topologically sorted.
5. **Render it twice from the same AST** — as SystemVerilog (`~ & | ^`) and as ngspice B-sources
   (`! && || !=`, since B-sources have no XOR operator).
6. **Self-check in Python** by evaluating the gold model over all `2^NI` vectors before writing
   anything, which also proves the model is loop-free and resolvable.
7. **Write** the testbenches, `reference_cells.spice`, `gold_functions.md`, and the two Makefiles
   and READMEs.

Output is deterministic: re-running on an unchanged netlist rewrites byte-identical files.

### Errors it refuses to generate through

The generator aborts with a message rather than emitting a testbench it cannot justify:

* **an instance that is not a standard cell of `--lib`** — a sub-module defined in the netlist
  itself, a cell from another library, or a typo. Without a Liberty entry there is no function to
  build a gold model from, so this is a hard error naming the offending modules;
* a cell that *is* in Liberty but has no `function` on an output pin — i.e. sequential or
  black-box cells, which this exhaustive-combinational scheme cannot check;
* a cell with no `.subckt` in the `--cell-spice` file(s);
* a `--custom-netlist` subckt whose ports do not match the expected order;
* an instance pin that is not a pin of that cell, or an unconnected cell output;
* an undriven or multiply-driven net, or a combinational loop (the cycle is printed);
* a module with more inputs than `--max-inputs`, or named by `--module` but absent from the netlist;
* a port name that would collide with an identifier the testbench template declares.

## What the testbenches check

Each testbench sweeps **every** input combination and compares the implementations bit by bit —
in SystemVerilog:

```systemverilog
wire [NO-1:0] diff    = dut_o ^ gold_o;
wire          correct = (diff === '0);
```

and in SPICE, as a strobed error signal per pair, thresholded at `VTH = VDD/2`:

```spice
Be_gold_ref e_gold_ref 0 V = abs(((v(g_O0)>0.5)?1:0)-((v(O0_ref)>VTH)?1:0))
Bc_gold_ref c_gold_ref 0 V = (v(clk)>0.5) ? v(e_gold_ref) : 0
```

A mismatch prints the offending vector and ends in `$fatal` (SV) or `quit 1` (ngspice), so the
simulator exits non-zero either way.

The gold model is **not** derived from the Verilog being tested — it comes from the Liberty
`function` attributes. Gold signals never read a DUT signal; only the netlist's *wiring* is shared
between the two models, and the cell semantics come from an independent source.
`tb/gold_functions.md` lists, per module, the Liberty function used for each instance, the emitted
gold equations, the outputs flattened down to the primary inputs, and the truth tables.

### Why not `sp2bool`?

The container ships lctime's `sp2bool`, which derives boolean functions straight from a transistor
netlist — the obvious oracle. It does not work on this PDK:

* `lctime/lccommon/net_util.py::get_channel_type()` calls a device NMOS only if its model name
  *starts with* `n`. IHP's models are `sg13_lv_nmos` / `sg13_lv_pmos`, so every transistor is
  treated as a PMOS and even `sg13g2_inv_1` comes out as `Y = True`.
* With the model names shimmed to `nmos_lv`/`pmos_lv`, it still mis-solves the deeper series
  stacks: `sg13g2_nand3_1`, `sg13g2_nand4_1` and `sg13g2_nor3_1` — 3 of the 16 cells used by
  `aion_cells.v` — come back as constant `True`/`False`.

The Liberty functions used instead were cross-checked against a direct transistor-network solve of
`sg13g2_stdcell.cdl` (union-find connectivity to VDD/VSS per input vector) and agree for every cell
used here. The `tb/spice/` layer is now a second, independent confirmation of the same thing: the
actual devices, simulated.
